## Up Next

- [ ] governance-conflict-resolution — When governance tries to merge an approved PR and gets a merge conflict, instead of failing, auto-resolve it using DeepSeek. Approach: add `actions/checkout` to `governance.yml`; when `gh pr merge` fails, checkout the repo, fetch the PR branch, attempt `git merge main`, then for each conflicted file call DeepSeek with the full conflict content + context about what both branches were trying to do (PR description + diff vs main changes), write the resolved file, commit and push back to the PR branch, then retry the merge. No enforcer review gate — we own the repo and trust the resolution. The existing `needs-enforcer-review` flow (for when authors push new commits after approval) should be removed or simplified since we're replacing it with direct auto-resolution. Needs `DEEPSEEK_API_KEY` secret (check if it already exists in the repo — the enforcer service uses it). Done when: PR #13 (forge, currently conflicted with main) gets auto-resolved and merged on the next governance run.

## Backlog

- [ ] persist-idea-events — Persist the full idea lifecycle to durable storage and enrich the event log. Right now ideas that don't reach quorum are lost (in-memory only) and the `/log` endpoint only tracks "exploring" actions. Changes needed: (1) persist every idea event to a log array that survives server restarts — submitted, voted on, promoted to active, assigned to agent, PR created (with PR #), completed/merged, discarded/timed-out; (2) enrich the existing event log with richer action types so the feed shows "kingashu proposed: Add a forge on the north bank", "peaceman voted on idea abc123", "kingashu opened PR #15", etc. not just "exploring". The `/log` endpoint should return all event types. Done when: you can see the full history of every idea ever submitted, including ones that died in the pool, and the event feed shows meaningful agent actions.

- [ ] agent-session-compaction — Prevent agents from hitting Claude token limits mid-session. After every 10 actions, the agent should: (1) write a concise summary of its current state to `memory.md` (position, active goal, recent observations, any idea it's working on) so context survives; (2) instead of calling `claude --continue` (which accumulates context), start a fresh Claude session that reads `memory.md` on boot. This gives each agent a clean context window every 10 actions while preserving continuity through the memory file. Safe to restart between actions because PR coding is handled by a detached background agent (see fast-idea-cadence) — the main loop is never mid-write. Done when: agents run indefinitely without hitting token limits and memory.md is visibly updated every 10 actions with a current-state snapshot.

- [ ] fast-idea-cadence — Make agents propose ideas and build PRs at high frequency for rapid testing. Two changes to the agent prompt instructions: (1) **Forced proposals**: every 3 actions the agent must call `/submit-idea` with a concrete world change idea before taking the next move — it can still move freely between proposals, but the counter is strict; (2) **Immediate PR coding on assignment**: when the server assigns the agent an idea (via `myAssignment` in `/idea-state`), the prompt must instruct the agent to immediately spawn a detached background `claude` process to write and open the PR, then continue playing — do not block the main loop waiting for the PR to finish. The background agent receives the idea description, the repo context, and instructions to open a PR in the style of prior merged PRs. This design also solves the session-compaction mid-PR problem: the main agent loop never touches PR code itself, so restarting it every 10 actions is always safe. Done when: agents visibly propose an idea every ~3 moves and a new PR appears on GitHub within a minute of an agent being assigned.
